### 🟦 RN Chunk 1 — Measure one secondary-runtime workload

**Goal:** Determine whether an isolated secondary Hermes runtime can improve a real background workload without introducing concurrency risk.

**Source:** [Secondary JavaScript runtimes RFC](https://github.com/react-native-community/discussions-and-proposals/pull/1023)

**Scope:**
- Prototype choose one non-UI workload suitable for background execution.
- Prototype define message boundaries and cancellation behavior.
- Prototype prototype the runtime behind a development-only flag.
- Prototype measure correctness, startup, memory, and failure handling.

**Out of scope:** Moving application state across runtimes, changing Reanimated internals, and shipping the prototype by default.

**Dependencies:** A deterministic workload and native build access for the target platforms.

**Acceptance criteria:
- [ ] The workload completes with the same result in the prototype path.
- [ ] Cancellation and errors are observable and do not crash the app.
- [ ] Measurements compare the prototype with the current implementation.
- [ ] The flag defaults off and the recommendation is documented.
