### 🟦 RN Chunk 3 — Benchmark the app's navigation startup path

**Goal:** Choose a navigation strategy based on repeatable cold-start, memory, FPS, and JavaScript measurements rather than anecdotal performance.

**Source:** [React Native Navigation Benchmarks](https://andrei-calazans.com/posts/2026-06-05-state-of-rn-navigation/)

**Scope:**
- Measure define one representative navigation flow and device matrix.
- Measure capture cold start, route transition, memory, and frame metrics.
- Measure run the same flow with the current router configuration.
- Measure publish a short baseline and one prioritized optimization.

**Out of scope:** Replacing the router, benchmarking every screen, and optimizing without a measurable regression target.

**Dependencies:** A fixed sample app flow, stable build configuration, and at least one Android test device.

**Acceptance criteria:
- [ ] The same flow can be repeated by a non-technical tester.
- [ ] Results include cold start, memory, FPS, and JS measurements.
- [ ] The baseline is stored with build and device versions.
- [ ] One optimization hypothesis is selected for a follow-up chunk.

- Evaluate run it with Hermes and the QuickJS alpha in a benchmark harness.

**Dependencies:** A native development build and a workload that does not require unsupported Hermes internals.
