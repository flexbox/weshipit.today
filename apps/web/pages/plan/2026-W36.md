### 🟦 RN Chunk 1 — Document the React Native C++ API boundary

**Goal:** Make native dependency upgrades safer by identifying whether the app or its modules rely on public, framework, or private React Native C++ APIs.

**Source:** [React Native C++ API RFC](https://github.com/react-native-community/discussions-and-proposals/pull/1018)

**Scope:**
- Implement inventory native modules and patches that include React Native C++ headers.
- Implement record each dependency's API tier and upgrade risk in a short compatibility document.
- Implement add a CI check or documented command that flags newly referenced private headers.
- Implement add one representative verification fixture for the current native build.

**Out of scope:** A full C++ migration, replacing third-party libraries, and changing the React Native version.

**Dependencies:** A working native build and access to the app's iOS/Android native dependencies.

**Acceptance criteria:
- [ ] The inventory identifies all app-owned C++ includes and their API tier.
- [ ] A reviewer can see which dependencies need migration before the next RN upgrade.
- [ ] The check fails clearly when a new private-header reference is introduced.
- [ ] The app still builds on the supported platform matrix.
